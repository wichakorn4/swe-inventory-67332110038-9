# AI-Generated Text Wireframes (ASCII Layouts) - Lab 04

เอกสารฉบับนี้บันทึก Prompt ที่ใช้สั่งการ AI ในการออกแบบ Text Wireframe (ASCII Layout) จำนวน 3 หน้าจอของระบบ Inventory Management System ภายใต้โควตาไม่เกิน 3 Prompt พร้อมผลลัพธ์ ASCII Layout และบทวิเคราะห์ด้าน Usability และ Accessibility ตามข้อกำหนดของห้องปฏิบัติการ

## Prompt ที่ 1: หน้า Login (เข้าสู่ระบบ)

### คำสั่ง Prompt (Prompt #1)
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Login" ของระบบ Inventory Management
กลุ่มเป้าหมายผู้ใช้: พนักงานคลังสินค้าและผู้จัดการ (ทักษะเทคโนโลยีระดับ 2/5, ใช้งานผ่าน PC จอภาพ 1080p เป็นหลัก)

ข้อกำหนดด้าน Usability:
- เลย์เอาต์เรียบง่าย สบายตา จัดวางฟอร์มกึ่งกลางหน้าจอ (Card container)
- มีช่องกรอก: ชื่อผู้ใช้/อีเมล (Username/Email)*, รหัสผ่าน (Password)*, ตัวเลือก "จดจำการเข้าสู่ระบบ" (Remember me), และลิงก์ "ลืมรหัสผ่าน" (Forgot password)
- ปุ่มเข้าสู่ระบบ (Primary Action) ขนาดใหญ่ ชัดเจน มีข้อความระบุชัดเจนว่า "เข้าสู่ระบบ (Sign In)" ไม่ใช่คำคลุมเครือ
- แสดง Error State กรณีล็อกอินไม่สำเร็จ: แสดงกล่องข้อความเตือนด้านบนพร้อมไอคอนเตือน และข้อความอธิบายวิธีแก้ไขที่เข้าใจง่าย (เช่น ตรวจสอบตัวพิมพ์ใหญ่-เล็ก หรือติดต่อ Admin)

ข้อกำหนดด้าน Accessibility (WCAG 2.1 AA):
- ทุกฟิลด์ต้องมี Persistent Label ด้านบนช่องกรอกตลอดเวลา (ห้ามพึ่งพาเพียง Placeholder)
- ช่องบังคับกรอกมีสัญลักษณ์ดอกจันสีแดง (*) กำกับชัดเจน
- มีปุ่มสลับการมองเห็นรหัสผ่าน (Show/Hide Password toggle)
- ลำดับการกด Tab (Focus Order) เรียงจากบนลงล่างอย่างเป็นธรรมชาติ

ขอผลลัพธ์เป็น ASCII layout พร้อมคำอธิบายว่าแต่ละองค์ประกอบสนับสนุน Usability และ Accessibility อย่างไร
```

### การวิเคราะห์ Usability & Accessibility (Login)
1. **Persistent Label**: ข้อความ "ชื่อผู้ใช้หรืออีเมล *" และ "รหัสผ่าน *" แสดงอยู่เหนือบ็อกซ์กรอกเสมอ ป้องกันผู้ใช้ลืมข้อมูลเมื่อเริ่มพิมพ์
2. **Accessible Error State**: แจ้งข้อผิดพลาดด้วยกรอบข้อความที่มีไอคอน `[!]` และคำแนะนำการแก้ไข (เช่น ตรวจ Caps Lock) ไม่พึ่งพาเพียงการเปลี่ยนสีกรอบเป็นสีแดง
3. **Button Clarity**: ข้อความบนปุ่มระบุชัดเจนว่า "เข้าสู่ระบบ (Sign In)" ไม่ใช้เพียงคำว่า "OK" หรือ "ส่ง"

## Prompt ที่ 2: หน้า Dashboard (ภาพรวมคลังสินค้าและการแจ้งเตือน)

### คำสั่ง Prompt (Prompt #2)
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Dashboard (ภาพรวมคลังสินค้า)" ของระบบ Inventory Management
กลุ่มเป้าหมายผู้ใช้: พนักงานคลังสินค้าและผู้จัดการ (ต้องรองรับสินค้า 2 ชนิด: สินค้าจับต้องได้ Physical และไฟล์ดิจิทัล Digital)

ข้อกำหนดด้าน Usability:
- Header ด้านบนแสดงชื่อระบบ, ชื่อผู้ใช้งานปัจจุบัน (คุณสุรศักดิ์), บทบาท (พนักงานคลัง), และปุ่มออกจากระบบ
- สรุปตัวเลขสถิติสำคัญ (KPI Metric Cards) แยกแยะชัดเจน:
  1) มูลค่ารวมสต็อกทั้งหมด (Total Warehouse Value)
  2) จำนวนสินค้าจับต้องได้คงเหลือ (Physical Stock Count)
  3) จำนวนรายการสินค้าดิจิทัล (Active Digital Items)
  4) รายการแจ้งเตือนสต็อกต่ำ (Low Stock Alerts)
- ปุ่ม Action หลัก "เพิ่มสินค้าใหม่ (+ Add New Product)" วางโดดเด่นทางขวาบน (Primary Blue Button)
- ตาราง Low Stock Alert Table แสดงสินค้าที่สต็อกต่ำกว่าหรือเท่ากับเกณฑ์ (<= 5 ชิ้น) พร้อมระบุรหัสสินค้า, ชื่อสินค้า, ชนิด, คงเหลือ, จุดสั่งซื้อ, และปุ่มกด "เติมสต็อก (+ Restock)" ทันที
- ตารางสรุปสินค้าล่าสุด แสดง Badge แยกชัดเจนว่ารายการใดคือ [Physical] หรือ [Digital] โดยไม่ต้องเดาจากชื่อสินค้า

ข้อกำหนดด้าน Accessibility:
- ตัวชี้วัดสถานะเตือนต้องมีทั้งไอคอนกำกับ [!] หรือ [*] ควบคู่กับข้อความบรรยาย ไม่ใช้สีส้ม/แดงอย่างเดียว
- Contrast สีพื้นหลังและตัวอักษรเป็นไปตามมาตรฐาน WCAG 2.1 AA (Text #111827 บนพื้นขาว, Primary #1E40AF, Warning #B45309)

ขอผลลัพธ์เป็น ASCII layout พร้อมคำอธิบาย
```

### การวิเคราะห์ Usability & Accessibility (Dashboard)
1. **Clear Distinction of Goods**: ในตารางมีคอลัมน์ "ชนิด" แสดง Badge `[Physical]` และ `[Digital]` ชัดเจน สินค้าดิจิทัลแสดงสถานะ `N/A (ไฟล์)` ไม่ถูกนำไปปะปนกับจำนวนชิ้นของสินค้าที่ต้องหยิบในโกดัง
2. **Prominent Call-to-Action**: ปุ่ม "+ เพิ่มสินค้าใหม่" ถูกเน้นทางด้านขวาบน สะดวกต่อพนักงานในการเริ่มฟังก์ชันรับเข้าสินค้า
3. **Multi-modal Alerting**: ตารางสินค้าใกล้หมดใช้ทั้งไอคอน `[!]`, ตัวเลขจำนวนคงเหลือ และป้ายเตือน `[!] 3 รายการ` เพื่อให้ผู้มีภาวะบกพร่องทางการมองเห็นสี (Color vision deficiency) เข้าใจความเร่งด่วนได้เท่าเทียมกัน

## Prompt ที่ 3: หน้า Add Product (แบบฟอร์มเพิ่มสินค้าใหม่)

### คำสั่ง Prompt (Prompt #3)
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Add Product (เพิ่มสินค้าใหม่)" ของระบบ Inventory Management
กลุ่มเป้าหมายผู้ใช้: คุณสุรศักดิ์ พนักงานคลังสินค้าทักษะระดับ 2/5 (กลัวการพิมพ์สลับช่องและสับสนประเภทสินค้า)

ข้อกำหนดด้าน Usability:
- ฟอร์มประกอบด้วยฟิลด์:
  1) ชนิดสินค้า* (Radio Selection: [ ] สินค้าจับต้องได้ (Physical) vs [ ] สินค้าดิจิทัล (Digital))
  2) ชื่อสินค้า* (Product Name)
  3) รหัสสินค้า* (SKU / Product Code)
  4) หมวดหมู่สินค้า (Category Dropdown)
  5) จำนวนสต็อกเริ่มต้น* (Initial Quantity) -> **กรณีเลือกสินค้าดิจิทัล ฟิลด์นี้ต้องถูก Disabled อัตโนมัติ พร้อมข้อความชี้แจง**
  6) ราคาต่อหน่วย* (Unit Price ในหน่วยบาท)
  7) อัปโหลดไฟล์รูปภาพหรือไฟล์เอกสาร (File Attachment - Optional)
- วางปุ่ม "บันทึกข้อมูล (Save Product)" (Primary Action) และปุ่ม "ยกเลิก (Cancel)" (Secondary) ที่มุมขวาล่าง
- แสดง State 2 กรณีในเลย์เอาต์:
  Case A: Validation Error ใต้ฟิลด์เมื่อกรอกผิดพลาด พร้อมข้อความอธิบายวิธีแก้ไขที่ชัดเจน
  Case B: Success Alert Banner ด้านบนเมื่อบันทึกข้อมูลสำเร็จ

ข้อกำหนดด้าน Accessibility (WCAG 2.1 AA):
- ทุกฟิลด์มี Persistent Label วางค้างอยู่ด้านบนของช่องตลอดเวลา (ไม่ใช้ Placeholder เดี่ยว ๆ)
- Required Fields มีเครื่องหมายดอกจันสีแดง (*) กำกับ
- Error State มีไอคอน [X] และข้อความบอกสาเหตุ ไม่ใช้สีแดงเพียงอย่างเดียว
- Focus order เป็นระเบียบ (Tab จากชนิด -> รหัส -> ชื่อ -> หมวดหมู่ -> จำนวน -> ราคา -> ปุ่มบันทึก)

ขอผลลัพธ์เป็น ASCII layout พร้อมคำอธิบาย
```

### การวิเคราะห์ Usability & Accessibility (Add Product)
1. **Persistent Floating Labels**: มีป้ายกำกับหมายเลขและชื่อฟิลด์ชัดเจนตลอดเวลา ทำให้พนักงานอย่างคุณสุรศักดิ์ไม่ลืมว่ากำลังกรอกฟิลด์อะไร
2. **Dynamic Adaptation for Digital Items**: การมี Radio ชนิดสินค้าพร้อมคำอธิบายพฤติกรรมตั้งแต่ข้อแรกช่วยป้องกันความผิดพลาด หากเลือกสินค้าดิจิทัล ระบบจะระบุทันทีว่าไม่ต้องกรอกจำนวนสต็อก
3. **Constructive Error Feedback**: ข้อความแสดงข้อผิดพลาดใต้ช่องกรอกมีไอคอน `[X]` และระบุเงื่อนไขที่ถูกต้องอย่างชัดเจน เช่น *"กรุณากรอกชื่อสินค้า ความยาวอย่างน้อย 3 ตัวอักษร"* แทนการขึ้นเพียงคำว่า *"Invalid input"*
4. **Button Hierarchy**: ปุ่ม "บันทึกสินค้า" ใช้ Primary Style ที่เด่นชัด ส่วนปุ่ม "ยกเลิก" ใช้ Secondary Style และเว้นระยะห่างป้องกันการคลิกผิดพลาด
